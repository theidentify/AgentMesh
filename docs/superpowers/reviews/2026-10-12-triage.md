## Accepted — fix in the guide

- **All professor items**, except terminology: prose uses **device identity**; use
  "node slot" only when explaining the `--node` value and the `<node>` in
  `status/<node>.json`. Define this once in Concepts.
- **Practitioner 2** (adding devices to a `setup-new` group): an invitation-based join
  is being implemented separately. Until it lands, `install/new-group.md` states that
  a `setup-new` group cannot add devices yet, and links nowhere broken.
- **Practitioner 5–11, 14–20**: document precisely — packet-level quarantine; managed
  worker stops on permanent failure, how to see why (`worker-status`, `diagnose`,
  the read-only diagnostics query if it is safe and stable) and what to do before
  restarting; missing/deleted exchange packets (never delete packets: deleting the
  newest packet loses data silently, an intermediate one leaves pending); signed
  packet size limits; same transcript ingested on several devices; timeouts; `outbox`
  meaning; growth of history and per-cycle cost; bootstrap size limits and their
  messages; partial ingest results; Hermes is recall-only (no ingestion); interval is
  a wait after each cycle; Windows launcher does not check prerequisites.
- **Community user**: per spec section "Expected output and prerequisites depth"
  (expected output after every command, real Syncthing steps, Python 3.10 vs 3.11,
  Quick start checklist and A → B test); one clear default path per situation
  (received a bootstrap vs. starting alone); "open a second terminal" where the
  worker occupies the first; quote paths that may contain spaces; concrete
  verification checklist for Linux/Windows hosts; a privacy-safe help-request
  template (`diagnose --json` fields to share); removing agent rules on uninstall
  (verify what `install_agent_rules.py` supports; otherwise list the files to delete).
